# 事件时序约束校验器（Temporal Constraint Checker）

用于**采访证词核对**与**事故复盘时间线分析**的 Web 应用。用户以自然语言形式录入约束：

> 事件 A 比事件 B **早 / 晚** `x` 到 `y` 分钟

再指定一个**锚点事件及其绝对时间**，系统实时将约束转换为**差分约束图**（Difference
Constraint System）并完成：

1. **可满足性实时判定** —— 约束间一旦矛盾（图中出现负环）立即报警；
2. **矛盾环高亮复核** —— 突出显示一条具体的矛盾环：图上红色节点/边、约束列表红色行，
   并逐条列出环上的差分不等式，求和得到 `0 ≤ 负数` 的代数证据，映射回原始证词；
3. **最小修复建议** —— 检测到矛盾时，以每次发现的负环为分支依据搜索
   **停用约束数量最少**的可满足方案；并列最优方案最多展示 5 个并按约束录入顺序稳定排序，
   每个方案列出需停用的约束与修复后的事件时间窗，支持**不写入 localStorage 的一键预览**
   与**确认应用**（确认后批量停用）。搜索累计超过 2000 个状态即停止，并明确标记结果可能不完备；
4. **时间窗计算** —— 可满足时给出每个事件相对锚点的**最早 / 最晚偏移**与对应的绝对时间；
5. **边界依据追溯** —— 点击时间窗表中任一事件的**最早 / 最晚时间**，展示从锚点推导该边界的
   **紧约束链**：按推导顺序逐步列出原始约束、采用的上/下界侧不等式与累计偏移，并在
   **差分图与约束列表中同步紫色高亮**；最早边界由反向图路径正确还原为原始约束（步骤标注「反向」）。
   锚点事件给出**零步证明**；单边无界或无法定时的单元格不可点击，悬停可见原因。
   任何编辑、切换锚点或进入/退出修复预览都会自动清除旧追溯，预览中的追溯按有效约束重新计算；
6. **无法定时标记** —— 与锚点在图上没有有向通路的事件标记为「无法定时」；
7. **分层最小偏差排程** —— 系统可满足且已设置锚点时，可为一个或多个非锚点事件填写
   **期望时刻**并为其指定**高 / 中 / 低**三级优先级（随状态持久化；旧数据默认「中」）。
   系统对**当前有效的整体差分系统**按 **高 → 中 → 低 做字典序最小化**：
   先求高优先级事件的最小最大偏差 `D高`（整体负环检测，非独立夹窗），
   **固定其最优容差**后再求中优先级的 `D中`，再固定后求 `D低`——
   **不使用加权和**（高层偏差永远优先取最小，不存在层级间权重折衷），
   **也不是各层分别排程后拼接**（每层求解都带上全部原约束与已固定层的钉住边），
   最终输出**一份**同时满足全部启用约束与所有层级容差的**确定性可行排程**：
   每个已定时事件的实际时刻、所属层级、相对期望的偏差、各层最优 D 与达到该层 ±D 的事件；
   仍未与锚点连通的事件明确标为「未定时」（其上的期望不参与搜索）。
   编辑约束、锚点、期望或层级后实时重算，矛盾状态下清空旧排程结果；
8. **示例数据 + 本地持久化** —— 内置「事故复盘（可满足）」与「采访证词冲突」两套示例，
   全部编辑内容（含期望时刻与高/中/低层级）自动保存在浏览器 `localStorage`
   （修复预览除外）；旧版本存档（无层级字段）可直接读取，层级默认按「中」处理。

技术栈：React 18 + TypeScript + Vite，纯前端、无后端依赖。

## 一条命令启动

需要已安装 Docker（含 Compose 插件）。在项目根目录执行：

```bash
docker compose up --build -d
```

启动后访问：

> **http://localhost:8080**

镜像构建时会自动完成依赖安装（`npm ci`）与生产构建（`tsc + vite build`），
容器启动即由 nginx 直接托管静态产物，**无需任何额外初始化步骤**。

常用命令：

```bash
docker compose logs -f        # 查看日志
docker compose down           # 停止并移除容器
docker compose up --build -d  # 代码更新后重新构建启动
```

### 修改访问端口

编辑 `docker-compose.yml` 的端口映射，例如改用 9090：

```yaml
ports:
  - "9090:80"
```

然后重新 `docker compose up -d`。

## 使用指南

1. **添加事件**：在「事件」面板录入关键时点（如：告警触发、服务恢复）；
2. **指定锚点**：点事件前的单选按钮，或使用顶部「锚点」下拉框，并设置锚点绝对时间；
3. **录入约束**：在「时序约束」面板选择 `事件 A —（早于/晚于）— 事件 B`，
   填写分钟区间 `x ~ y`（要求 `0 ≤ x ≤ y`；`x = y` 表示精确间隔）；
4. **查看实时结论**：
   - 顶部绿色横幅：系统可满足，底部表格给出每个事件的时间窗；
   - 红色横幅：存在矛盾，红色矛盾环给出可逐步复核的不等式链；其下方「最小修复建议」
     给出停用约束最少的方案；
   - 黄色「无法定时」：该事件与锚点之间没有任何约束通路，请补充连接二者的约束；
5. **追溯边界依据**：在时间窗表中点击任一事件的**最早时间**或**最晚时间**，
   表下方展开该边界的推导链——从锚点出发逐步列出用到的原始约束（含录入序号）、
   采用的上界/下界侧不等式与累计偏移，差分图与约束列表同步紫色高亮；
   再次点击同一单元格或点击「关闭」收起。锚点事件点击后显示零步证明；
   单边无界 / 无法定时的单元格不可点击，悬停可查看原因。
   编辑数据、切换锚点或进入/退出修复预览会自动清除当前追溯；
6. **核对矛盾**：可逐条**取消勾选**可疑证词，观察矛盾环是否消失，快速定位冲突来源；
7. **分层最小偏差排程**：系统可满足且已设置锚点时，底部「分层最小偏差排程（高 → 中 → 低）」
   面板可为任意非锚点事件填写**期望时刻**（留空则不参与），并在右侧下拉框选择
   **高 / 中 / 低**层级（默认「中」，选择随状态持久化）。系统对**同一个整体差分系统**
   按字典序实时求解：
   - 先求**高优先级**的最小最大偏差 `D高`（使全部启用约束与高层期望「实际 ∈ 期望 ±D高」
     同时可满足）；
   - **固定高优先级的最优容差**（高层事件永久钉住在该容差内），再求**中优先级**的
     最小 `D中`；
   - 再固定后求**低优先级**的最小 `D低`。

   整个过程不使用加权和、也不是各层分别排程后拼接：每一层的可行性都在包含全部原约束与
   已固定层钉住边的**同一张图**上做整体负环检测。面板上方三张层级卡片分别给出
   各层最优 D、参与事件数与**达到该层 ±D 的事件**；下方汇总字典序最优容差
   `(D高, D中, D低)` 与本排程最大偏差；结果表逐事件列出**层级、实际时刻、相对锚点偏移、
   期望时刻与期望偏差**，达到本层容差边界的偏差带「达到 ±D」标记。
   未与锚点连通的事件在结果中明确标为「未定时」，其上填写的期望不参与搜索并会注明未生效。
   编辑约束、锚点、期望时刻或层级后排程实时重算；约束矛盾时面板清空旧结果、不展示任何过期排程；
8. **采纳修复建议**：
   - 点击方案卡片上的**一键预览**：相关约束被临时停用（置灰并标记“预览停用”），
     图与时间窗立即按修复后的状态展示；预览**只存在于内存，不写入 localStorage**，
     可随时「退出预览」返回原数据，任何编辑操作也会自动退出预览；
   - 点击**确认应用**：方案中的约束被**批量停用**并持久化；
   - 并列最优方案超过 5 个时只展示按约束录入顺序最靠前的 5 个（会注明总数）；
     搜索累计达到 2000 个状态仍未结束时，面板会提示**结果可能不完备**。

### 状态图例（时间窗表）

| 状态 | 含义 |
| --- | --- |
| **锚点** | 时间即用户指定的锚点绝对时间 |
| **可定时** | 最早与最晚偏移都能由约束推出 |

## 算法说明

每条约束 `A 比 B 早 x~y 分钟`（即 `x ≤ t_B − t_A ≤ y`）转换为两条
**差分不等式**，在图中对应两条带权有向边（边 `u → v` 权 `w` 表示 `t_v − t_u ≤ w`）：

- 上界：`t_B − t_A ≤ y` ⇒ `A → B, 权 y`
- 下界：`t_A − t_B ≤ −x` ⇒ `B → A, 权 −x`

`A 比 B 晚 x~y` 时方向互换。

- **可满足性**：差分系统可满足 ⇔ 图中不存在负权环。使用带「超级源点」（全部节点初始
  距离为 0）的 Bellman-Ford 在第 n 轮检测松弛，时间复杂度 O(V·E)，对复盘场景规模足够；
- **矛盾环提取**：从第 n 轮仍被松弛的边沿前驱指针回溯，先走入环内再裁掉环外尾巴，
  得到一条权重之和严格小于 0 的环；
- **时间窗**：以锚点为源跑最短路得到各事件「最晚偏移」`t_i − t_anchor` 的最小上界；
  在反向图上跑最短路得到「最早偏移」。正/反向均不可达即为「无法定时」。
- **边界依据追溯**：可满足时，最短路的前驱边即从锚点出发的紧约束链。
  最晚边界直接沿正向图前驱边回溯；最早边界在反向图上取前驱边后，
  逐步还原为原始约束边（行走方向与原始边相反，权重与上/下界侧不变），
  累计偏移为路径权重前缀和（最早边界取负）。锚点自身为零步证明。
- **最小修复建议**：在「停用哪些约束可使系统恢复可满足」中求**停用数最少**的方案
  （最小击中集）。采用以负环为分支依据的逐层 BFS（branch and bound）：
  1. 对当前停用集合跑一次 Bellman-Ford；
  2. 若已无负环，当前集合即为可行方案；
  3. 否则任取一条负环 C——任何可行方案都必须再停用 C 上的至少一条约束，
     故只需对 C 上的不同约束逐一分支，完备且不会枚举无关约束；
  4. 按停用数 0,1,2,… 逐层展开，**第一次出现可行方案的层即给出最少停用数**，
     同层全部状态都会被考察，以收集并列最优方案；候选项按约束录入顺序展开，
     同层方案按停用约束的录入顺序字典序稳定排序，最多展示 5 个。

  搜索用全局 visited 集合（停用集合的规范化下标元组）去重；累计访问状态数达到
  **2000** 上限即停止：若已找到方案，最少停用数仍已被证明（但并列方案列表可能不全）；
  若尚未找到方案，则明确标记结果可能不完备。每个候选方案复用 `analyze` 计算修复后时间窗。
- **分层最小偏差排程（高 → 中 → 低 字典序最小化）**：设期望事件 `i` 相对锚点的期望偏移为
  `d_i`（由期望时刻与锚点时间相减得到，分钟取整），所属层级为 `p_i`。对层级 L 定义
  `D_L = max_{i: p_i = L} |t_i − d_i|`。对候选容差 `D`，把对应事件「钉」到锚点上：
  加边 `anchor → i, 权 d_i + D` 与 `i → anchor, 权 D − d_i`，即
  `d_i − D ≤ t_i − t_anchor ≤ d_i + D`。

  字典序最小化 `(D高, D中, D低)`（**不是加权和，也不是分别排程后拼接**）：
  1. **高层**：在原边 + 高层钉住边的**整体**图上做负环检测，求最小可行非负整数 `D高`；
  2. **固定**：把高层钉住边按 `D高` 永久并入图中（高层容差在后续求解中不得放松）；
  3. **中层**：在「原边 + 高层钉住边 + 中层候选钉住边」的同一张图上求最小 `D中`，
     再固定；低层同理。
  4. **输出**：三层全部钉住（容差取各自最优值）后的一组可行势（锚点平移到 0）。
     边集与边顺序确定时 Bellman-Ford 结果确定，故输出为确定性排程。

  单层最小容差的搜索结构：
  1. **上界**：当前已钉住图的任一可行势 `t*`（超级源点 Bellman-Ford）给出可行上界
     `D_ub = max_{i ∈ 本层} |t*_i − d_i|`；
  2. **二分**：在 `[0, D_ub]` 上二分最小的可行非负整数。

  由于每层在其求解阶段 `D − 1` 不可行，而后续层只追加钉住边、不放松约束，
  输出排程中每个非空层都必然有事件达到该层 ±D_L。

  为什么不能用「加权和」：加权和允许以增大高层偏差为代价换取低层更小的偏差，
  破坏「高层诉求必须最先被满足」的语义；字典序下 `(5, 10)` 严格优于 `(8, 8)`
  （首分量 5 < 8），即便二者之和 15 < 18。
  为什么不能用「各层分别排程后拼接」：不同层级的事件可能被同一组约束耦合，
  分别求得的排程拼在一起可能违反原约束；本算法每层都在含全部原约束与已固定层钉住边的
  整体图上判可行性，天然保证最终唯一排程同时满足全部启用约束。

  为什么不能用「各事件独立夹到现有时间窗」：事件间存在耦合。例如约束
  `t_Y = t_X + 5` 时，窗口为 `X∈[0,5]`、`Y∈[5,10]`；若期望 `X=+10`、`Y=0`，
  独立夹窗会把 `X` 夹到 5、`Y` 夹到 5（各偏差 5）而误判 `D=5`，
  但 `t_X=5 ⇒ t_Y=10`（偏差 10）——整体搜索给出的正确答案（同层时）是 `D=8`；
  若 `X` 为高层、`Y` 为低层，字典序答案则是 `(D高, D低) = (5, 10)`。
  与锚点不连通的事件不参与搜索，在结果中标记为「未定时」。
